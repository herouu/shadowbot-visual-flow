# 可视化数据流设计模式（踩坑抽象）

每条：**适用场景 → 做法 → 反例**。与 `excel-blocks.md` 互补：那边讲积木字段，这边讲怎么搭。

## 1. 跨作用域状态：外层容器 + 原地 mutate
- 适用：try / for / if 里要累积结果，作用域外还要读。
- 做法：**顶层**先建 `dict`/`list`（`programing.variable`），块内只做 `state['key'] = ...` 这类**原地修改**；结果天然外泄。
- 反例：指望 `for` 或 `try` 内新赋值的变量在块外可见 —— 拿不到（或报 `variable_out_of_scope`）。注意**产出实例的积木（打开工作簿等）必须放 `try` 之前**，否则 catch 也取不到句柄。

## 2. 单表达式聚合，胜过"循环 + 中间表"
- 适用：整列求 max / 名次 / 去重 / 归一。
- 做法：在**一条赋值积木的 expression** 里用列表推导 + lambda 一次算完，`E("...")` 直填。少几十个块，也少几十个错点。
- 反例：为归一化搭一个循环 + 临时数据表格，块数翻倍、中间态难调，且临时表变量同样逃不出作用域。

## 3. 幂等键：写前先剔除旧记录
- 适用：写库 / 写表，可能重复运行。
- 做法：按「业务键 + 批次（日期）」先删同键旧行再写新行；键要保证**唯一**。
- 反例：直接追加 → 同日重跑产生重复数据，下游统计翻倍。

## 4. 只写目标行 + 整行透传
- 适用：大表里只有少数行需要变更。
- 做法：逐行判定，命中则改指定列，**未命中行整行原样写回**（最小改动面）。
- 反例：为了统一口径对全表跑转换 —— 一行脏值抛异常，整轮结果作废；且历史行被无意义改写，diff 不可读。

## 5. 哨兵值 + 变更计数
- 适用：需要区分"未处理/未命中"和"真的 0"。
- 做法：哨兵取 `-1`（或空串），取值处显式给默认值；维护一个 `changed` 计数器，**写盘 gate = `changed > 0`**。
- 反例：gate 用「结果容器长度 > 0」→ 全 0 一轮也照写，白改一遍还打"成功"日志。

## 6. 防空覆盖（保旧数据）
- 适用：结果直接覆盖已有数据表 / 数据文件。
- 做法：本轮结果为空 → **跳过写入**，只写告警 + 日志，让上一轮好数据留着。
- 反例：空结果照写 → 表被清空，等于用一次失败覆盖掉全部历史。

## 7. 去重 / 择优：排序后按主键取首条
- 适用：同一主键出现多行，要留一条。
- 做法：先按优先级排序（如「非付费优先 → 指标最大」），再**按主键取首条**；一个主键恰好一行。
- 反例：用 `any(...)` 判定"是否已收录"式的布尔去重 → 判据冲突时并列双留，后续按主键查出现两条。

## 8. 归一化选择：名次归一 + 常量列置 0 + 只用完整行
- 适用：多维度加权打分、排序。
- 做法：
  - **名次归一** `(N - rank + 1) / N`，抗离群、不假设分布；线性 `(x-min)/(max-min)` 被极值单点带偏。
  - **常量列（max == min，含整列全 0）该维统一记 0**，否则排序会凭空造出区分度（虚假高分）。
  - **只让"数据完整"的行参与排名**：缺失行的 0 会被排到中高位，与完整行不可比。
- 反例：全表参与排名且不做完整行过滤 —— 大量未填数据的行拿到高分（实测一批 90 行里 80 行缺失 → 排出 89 个"高分"，实际不可比）。

## 9. 外部受限资源：单轮预算 + 熔断
- 适用：调用有配额 / 易被限流的外部接口。
- 做法：单轮预算计数器 + 失败/异常计数器；任一超阈值 → **停发 + 写告警 + 结束本轮**。切换渠道时**局部计数复位、全局熔断计数保留**。
- 反例：每换一个渠道就把所有计数清零 → 所有渠道都被限还继续打，把配额和账号一起打废。另外别按「总调用数」代替「成功数」做 gate。

## 10. 失败判定要区分形态
- 适用：外部接口返回不可控。
- 做法：**软降级 = 返回体结构不对**（如首字符不是 `{` / `[`、缺关键字段）；**"结构正常但结果为空"不算失败**。
- 反例：把"空结果"也当失败 → 触发无意义退避 / 切渠道，越切越乱；反之把"结构错"当空结果 → 静默丢数据。

## 11. 增益环节 best-effort，关键环节 fail-fast
- 适用：流程里有主链和增强步骤。
- 做法：非关键增强失败 → **写告警 + 错误日志，不抛异常**，主链继续；关键步骤（写盘、主数据获取）则立刻失败并显式收尾。
- 反例：给可选增强加 `programing.raise` → 一次可选失败终止整轮；或全流程都用 catch 吞掉 → 真故障被埋。

## 12. 异常可见 + 告警落盘
- 适用：所有带 `try` 的流程。
- 做法：`catch` 输出 `exception`（str），**必须 `programing.log` 打印 `str(exception)`**；同时把「时间 / 环节 / 原因 / 计数」**追加写进告警文件**（`file.write` + `write_way=append`）。
- 反例：catch 里只打固定文案"处理失败" → 真因被吞，只能靠猜；只打运行日志不落盘 → 日志被滚动冲掉，无人知晓。

## 13. 回滚点：流程本体不在版本控制里
- 适用：改流程 / 重建流程。
- 做法：改动前先备份**建流脚本**并留回滚点（脚本才是 source of truth）；建流封装通常是 `clear → insert → fill`，**fill 失败会留下"已被清空"的流程**，不算恢复完成，必须修到 fill + 诊断通过。
- 反例：直接改线上流程、不留脚本备份 —— 改坏了没有可比对的基线。
