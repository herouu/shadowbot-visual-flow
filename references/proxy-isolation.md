# 代理出口隔离：一个身份 = 一个入站 listener

多账号 / 多环境轮换时，如何做到「身份 ↔ 出口」硬绑定且互不串用。客户端实例：**Clash Verge（mihomo 内核）** 或任何支持**多入站监听（listener）**的本地代理客户端。

## 1. 要解决什么问题（模式）

- 场景：一个流程要轮换多个「身份」，每个身份 = 一组账号 + 一个浏览器（指纹）环境 + 一个出口 IP。
- 目标：身份之间**彻底隔离** —— 换身份时同时换出口、换会话、换指纹，且**不需要重启**任何程序（浏览器与代理内核常驻）。
- 反模式 A：所有身份共用同一出口 → 一个被限，全员被限，「切换身份」形同虚设。
- 反模式 B：运行中临时改出口（同一端口换上游节点）→ 身份与出口不再一一对应，事后无法回放/追责，行为也更可疑。
- 反模式 C：每个身份起一个独立代理客户端实例 → 内核实例与端口管理爆炸，极易串用。

## 2. 做法：逐入站 listener（端口钉节点 + 独立认证）

在客户端配置里为**每个身份**加一个入站监听：

- `type: socks`（或 `http`）；`listen: 127.0.0.1`；**每身份一个固定端口**。
- 该 listener 的 `proxy` **钉死到某个具体上游节点**（写节点，不写规则组）。
- 每个 listener 配**独立的 `users`**（用户名 + 口令）。

```yaml
listeners:
  - name: env-01
    type: socks
    listen: 127.0.0.1
    port: 20001
    proxy: "<上游节点名·须与订阅内节点名逐字符一致，含 emoji>"
    users:
      - username: env01
        password: "<独立口令·占位>"
  - name: env-02
    type: socks
    listen: 127.0.0.1
    port: 20002
    proxy: "<另一个上游节点>"
    users:
      - username: env02
        password: "<独立口令·占位>"
```

要点（均为实测踩过的）：

- `proxy` 必须与订阅里的节点名**逐字符一致（含 emoji / 空格）**，写错内核会直接报错启动失败。
- 端口要**避开客户端自身默认端口**（如混合端口 `7897` 之类），否则冲突。
- 绑 `127.0.0.1`：只允许本机连接，不对外暴露。
- 这些 listener 通常**不在 GUI 的可视化管控字段里** → 写进 profile 的扩展 / Merge 配置段，避免 GUI 保存时被丢弃，也避免被 GUI 的「全局代理」开关改道。
- 每个 listener 独立 `users`：即使端口填错串了身份，也会因**认证失败而暴露**，而不是悄悄用错出口。
- 身份数量增加只是**追加一个 listener + 一个端口**，不改动已有身份。

## 3. 接到浏览器 / 环境上

- 指纹环境（或浏览器启动代理参数）里填：`socks5` + `127.0.0.1` + 该身份的**端口** + 该 listener 的用户名 / 口令。
- 一个身份固定一个 listener；**同一身份生命周期内不换端口**。
- 建模（推荐）：账号表加一列「环境 id」，出口由**环境自身的代理配置**承载 → **账号 ↔ 环境 ↔ 出口**三者天然绑定，所谓「换身份」就是换环境 id。

## 4. 校验（必须实测，不要只信配置）

```sh
curl -x socks5h://<user>:<pass>@127.0.0.1:<port> http://ip-api.com/json/?fields=query,country,isp
```

- 校验点：① 出口 IP 与预期节点一致 ② 各身份出口**互不相同** ③ 认证生效（故意用错口令必须明确失败）。
- 也可在流程内做同样的事（HTTP 请求积木 + 把出口写进日志/数据表），事后能核对「某次运行走的哪个出口」。

## 5. 排查清单（现象 → 原因 → 做法）

- 端口连不上 → listener 未生效 / 端口被占：`netstat -ano` 看端口是否在监听；确认配置已加载（重启内核或重载配置）。
- 认证失败 → `users` 与实际填写不一致（端口串用、口令写错）。
- 内核启动报错 → `proxy` 节点名写错（必须与订阅节点名逐字符一致，含 emoji）。
- 出口 IP 与预期不符 → 该 listener 未绑定成功（回落到了默认出口），或客户端的「全局代理 / 规则」在起作用。
- 本地走代理失败但直连外网正常 → 客户端开了「绕过 / 系统代理」类开关，或本地回环被代理接管。
- 换了出口业务仍受限 → 光换 IP 不一定够（会话 / 指纹 / 账号本身也是判定维度）→ **换身份要整体换**（出口 + 环境 + 会话），而不是只换 IP。

## 6. 与流程设计的配合

- 多身份轮换的循环结构、失败切换、计数与全局熔断、结果统一汇总写盘 —— 见 `SKILL.md` 的「多身份轮换」一节与 `references/patterns.md`。
- 原则：**局部失败只换身份，不换出口**；全局连续失败才熔断停轮。
